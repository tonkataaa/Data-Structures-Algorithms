# Hash Tables (Hash Maps / Dictionaries)

> В различните езици се срещат под различни имена:
>
> - **JavaScript** → `Object` / `Map`
> - **C#** → `Dictionary<TKey, TValue>`
> - **Python** → `dict`

---

# Пример

```text
basket["grapes"] = 1000

Ключ: "grapes"
        │
        ▼
 Hash Function
        │
        ▼
 Memory[711] = 1000
```

Получаваме стойността чрез ключа, без да обхождаме цялата структура.

---

# Какво е Hash Function?

Hash Function е функция, която приема входни данни (ключ) и връща число с фиксирана дължина (Hash Code).

Пример:

```text
Input:
hello

MD5:
5d41402abc4b2a76b9719d911017c592
```

## Основни свойства

- Един и същ вход винаги връща един и същ hash.
- От hash-а не можем лесно да възстановим оригиналния вход.
- Дори малка промяна в текста води до напълно различен hash.

Например:

```text
hello
↓

5d41402abc4b2a76b9719d911017c592
```

```text
Hello
↓

8b1a9953c4611296a827abf8c47804d7
```

---

# Защо Hash Tables са бързи?

Hash функцията казва директно къде в паметта се намира елементът.

Не се налага да обхождаме всички елементи.

---

# Time Complexity

| Операция | Средно |
|----------|---------|
| Insert | **O(1)** |
| Lookup | **O(1)** |
| Delete | **O(1)** |
| Search | **O(1)** |

---

# Hash Collision

Collision възниква, когато два различни ключа генерират един и същ hash.

```text
apple
   │
   ▼
 Hash = 5
        │
orange ─┘
```

И двата ключа попадат в един и същи bucket.

Тогава структурата трябва да провери кой от елементите е правилният.

В най-лошия случай производителността може да стане:

```
O(n)
```

---

# Keys()

В **C# Dictionary** можем да използваме:

```csharp
dictionary.Keys
```

Това връща колекция от всички ключове.

Пример:

```csharp
foreach(var key in dictionary.Keys)
{
    Console.WriteLine(key);
}
```

## Complexity

- Достъп до `Keys` → **O(1)**
- Обхождане на всички ключове → **O(n)**

---

# Hash Tables vs Arrays

| Arrays | Hash Tables |
|---------|-------------|
| ✅ Бърз достъп по индекс | ✅ Бърз достъп по ключ |
| ✅ По-малко памет | ✅ Insert/Delete → O(1) |
| ✅ Запазват реда | ✅ Гъвкави ключове |
| ❌ Insert/Delete → O(n) | ❌ Използват повече памет |
| ❌ Фиксиран размер | ❌ Не пазят ред |
| | ❌ Възможни Collisions |

---

# Предимства

- Бързи търсения
- Бързо добавяне
- Бързо изтриване
- Позволяват използването на различни типове ключове

---

# Недостатъци

- Не пазят реда на елементите
- Използват повече памет
- Възможни са Hash Collisions
- Итерацията по ключовете е по-бавна

---

# Практическо приложение

Hash Tables често се използват за оптимизация.

Например можем да заменим алгоритъм със сложност:

```
O(n²)
```

с алгоритъм със сложност:

```
O(n)
```

като използваме Hash Table вместо вложени цикли.

Два последователни цикъла (**O(n)**) почти винаги са по-добри от един вложен цикъл (**O(n²)**).
